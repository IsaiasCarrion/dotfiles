# DMS (DankMaterialShell) en este repositorio

DMS es el shell del escritorio (niri + Quickshell). **Administra su propia configuración** y la
regenera. Por eso el repositorio de dotfiles no la stowea ni la edita: solo instala el stack y
respeta los archivos que DMS considera suyos.

## Stack instalado

Los paquetes vienen de los COPR `duxlabs/dms`, `duxlabs/dux-repo` y `yalter/niri`
(`packages/dms.txt`):

- `niri`
- `dms`
- `ghostty`
- `quickshell`
- `matugen`
- `dux-greeter`
- `dux-search`
- `dux-calendar`
- `dux-files`

`packages/copr.txt` es la lista de repositorios que el bootstrap habilita **solo si falta algún
paquete del stack**. Los COPR son de terceros: revisalos antes de confiar en ellos.

## Archivos administrados por DMS (no tocar)

| Ruta | Qué contiene |
|---|---|
| `~/.config/dms/` | `settings.json`, `plugins.lock.json`, CSS, changelog y estado interno |
| `~/.config/niri/dms/*.kdl` | `binds.kdl`, `colors.kdl`, `outputs.kdl`, `input.kdl`, `layout.kdl`, `alttab.kdl`, `windowrules.kdl`, `cursor.kdl`, `wpblur.kdl` |
| `~/.config/niri/config.kdl` | Config principal de niri, con `include optional=true "dms/..."` |
| `~/.config/ghostty/themes/dankcolors` | Tema de Ghostty generado por DMS |

Los encabezados de `~/.config/niri/dms/*` dicen “DO NOT EDIT / AUTO-GENERATED BY DMS”. Si necesitás
cambiar algo, hacelo desde la interfaz de DMS o desde `dms config`, no desde el repo.

### Atajos de teclado

Los atajos actuales están en `~/.config/niri/dms/binds.kdl` (por ejemplo `Mod+O` para el
overview). El repositorio **no** versiona ese archivo. Cambialos desde DMS; si los copiás al repo,
la próxima regeneración de DMS los pisará.

### Tema de Ghostty

DMS genera `~/.config/ghostty/themes/dankcolors` a partir de la paleta activa. El repo guarda
`assets/ghostty/dankcolors` solo para que Ghostty tenga un tema válido en el primer arranque,
antes de que DMS lo genere.

`scripts/deploy-dotfiles.sh` copia el fallback **únicamente si el archivo no existe**. Nunca
sobrescribe el tema administrado.

## Qué stowea el repositorio

- `ghostty/.config/ghostty/config` → `~/.config/ghostty/config` (configuración principal).
- `opencode/.config/opencode/*` → configuración de OpenCode (ver `docs/opencode.md`).
- `bash`, `bash-dnf` y `git`.

Nada de `~/.config/dms` ni de `~/.config/niri/dms`.

## Instalación en un equipo nuevo

```bash
cd ~/dotfiles
./bootstrap.sh
```

El bootstrap:

1. habilita los COPR si falta algún paquete del stack;
2. instala `packages/dms.txt`;
3. verifica con `./scripts/verify.sh`.

En el primer inicio, DMS crea `~/.config/dms` y `~/.config/niri/dms`, y genera el tema de Ghostty.
No copies esos archivos desde otro equipo salvo que quieras restaurar una configuración concreta.

## Diagnóstico

```bash
dms doctor                 # dependencias e instalación
dms config --help          # utilidades de configuración
dms backup --help          # respaldo/restauración propia de DMS
niri validate -c ~/.config/niri/config.kdl
ghostty +validate-config
```

Si `dms doctor` falla, revisá primero:

```bash
dnf repolist --enabled | grep -E 'duxlabs|niri'
rpm -q dms ghostty quickshell matugen
```

## Actualizaciones

```bash
sudo dnf upgrade --refresh
```

DMS y niri se actualizan desde sus COPR. Después de actualizar:

```bash
dms doctor
niri validate -c ~/.config/niri/config.kdl
ghostty +validate-config
```

## Problemas frecuentes

| Síntoma | Solución |
|---|---|
| Falta un paquete DMS | `dnf repolist --enabled`; habilitá `duxlabs/dms` y `duxlabs/dux-repo`; `sudo dnf install <paquete>` |
| DMS pisa un cambio manual | Es esperado: ese archivo es administrado. Cambiá desde DMS. |
| El tema de Ghostty no existe | `./scripts/deploy-dotfiles.sh` copia el fallback si falta; luego DMS lo regenera. |
| niri no arranca tras un update | `niri validate -c ~/.config/niri/config.kdl` y revisá los includes `dms/*.kdl`. |
| Atajos distintos a los esperados | Revisá `~/.config/niri/dms/binds.kdl`; no edites el repo para eso. |

## Restaurar la configuración de DMS

El repo no la versiona. Para moverla entre equipos usá el mecanismo propio de DMS:

```bash
dms backup --help
```

Si necesitás una copia manual, hacela **fuera** del repositorio de dotfiles y no la stowees.
