# DMS (DankMaterialShell) y niri

DMS y niri son parte de la instalación de **CachyOS**. Este repositorio **no los
instala, no los actualiza y no administra su configuración**. El bootstrap no
toca paquetes ni archivos del escritorio; solo instala herramientas personales.

## Qué administra el sistema

| Ruta | Qué contiene |
|---|---|
| `~/.config/dms/` | `settings.json`, plugins, CSS y estado interno |
| `~/.config/niri/dms/*.kdl` | `binds.kdl`, `colors.kdl`, `outputs.kdl`, `input.kdl`, `layout.kdl`, etc. |
| `~/.config/niri/config.kdl` | Config principal de niri, con `include optional=true "dms/..."` |
| `~/.config/ghostty/themes/dankcolors` | Tema de Ghostty generado por DMS |

Los encabezados de `~/.config/niri/dms/*` dicen “DO NOT EDIT / AUTO-GENERATED BY
DMS”. Si necesitás cambiar algo, hacelo desde la interfaz de DMS o desde
`dms config`, no desde el repositorio.

## Qué stowea este repositorio

- `ghostty/.config/ghostty/config` → `~/.config/ghostty/config`.
- `opencode/.config/opencode/*` → configuración de OpenCode.
- `bash`, `bash-arch`, `git`, `starship` y, si `delta` existe, `git-delta`.

Nada de `~/.config/dms`, `~/.config/niri/dms` ni `~/.config/niri/config.kdl`.

## Tema de Ghostty

DMS genera `~/.config/ghostty/themes/dankcolors` a partir de la paleta activa. El
repo guarda `assets/ghostty/dankcolors` solo para que Ghostty tenga un tema
válido en el primer arranque, antes de que DMS lo genere.

`scripts/deploy-dotfiles.sh` copia el fallback **únicamente si el archivo no
existe**. Nunca sobrescribe el tema administrado.

## Instalación

```bash
cd ~/dotfiles
./bootstrap.sh
```

El bootstrap **no** habilita repositorios de terceros ni instala `niri`, `dms`, `ghostty`,
`quickshell`, `matugen` ni `dux-*`. Si el escritorio ya está instalado por
CachyOS, se respeta tal cual. Si falta, se instala desde la imagen de CachyOS o
con los medios que el sistema provea; este repo no es el lugar para hacerlo.

En el primer inicio, DMS crea su configuración y el tema de Ghostty. No copies
esos archivos desde otro equipo salvo que quieras restaurar una configuración
concreta.

## Diagnóstico

```bash
dms doctor                 # dependencias e instalación
dms config --help          # utilidades de configuración
dms backup --help          # respaldo/restauración propia de DMS
niri validate -c ~/.config/niri/config.kdl
ghostty +validate-config
```

## Actualizaciones

DMS y niri se actualizan con el resto del sistema:

```bash
sudo pacman -Syu
```

Después de actualizar:

```bash
dms doctor
niri validate -c ~/.config/niri/config.kdl
ghostty +validate-config
```

## Problemas frecuentes

| Síntoma | Solución |
|---|---|
| DMS pisa un cambio manual | Es esperado: ese archivo es administrado. Cambiá desde DMS. |
| El tema de Ghostty no existe | `./scripts/deploy-dotfiles.sh` copia el fallback si falta; luego DMS lo regenera. |
| niri no arranca tras un update | `niri validate -c ~/.config/niri/config.kdl` y revisá los includes `dms/*.kdl`. |
| Atajos distintos a los esperados | Revisá `~/.config/niri/dms/binds.kdl`; no edites el repo para eso. |
| Falta un paquete del escritorio | Se resuelve desde CachyOS, no con este bootstrap. |

## Restaurar la configuración de DMS

El repo no la versiona. Para moverla entre equipos usá el mecanismo propio de DMS:

```bash
dms backup --help
```

Si necesitás una copia manual, hacela **fuera** del repositorio y no la stowees.
